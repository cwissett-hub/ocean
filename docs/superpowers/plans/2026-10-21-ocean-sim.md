# Ocean Sim Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A custom Rust + wgpu real-time sunset ocean (FFT waves, Jacobian foam, hardware ray-traced reflections of waves and a floating buoy, faked spray, live settings panel) holding 60 fps in a 1280×720 window on the RTX 2000 Ada laptop.

**Architecture:** One binary crate with a `lib` for everything testable. All per-frame work is GPU compute + raster through wgpu's **Vulkan** backend (ray queries are Vulkan-only in wgpu 30). The frame is: wave sim (spectrum → FFT → assemble + foam) → RT patch + acceleration structures → G-buffer raster (ocean + buoy) → reflections (RT or screen-space, half-res) → shading composite (HDR) → particles → bloom + tonemap → egui. Wave spectra and `h0` are generated once on the CPU and uploaded, so a CPU reference evaluator and the GPU produce the same field and can be compared in tests.

**Tech Stack:** Rust 1.96 (edition 2024); wgpu 30.0.1 (`EXPERIMENTAL_RAY_QUERY`), winit 0.30.13, egui / egui-wgpu / egui-winit 0.37.0, glam 0.34.1, bytemuck 1.25, rustfft 6.4.1 (CPU reference only, dev + test), naga 30.0.1 (`wgsl-in`, for CPU-side shader validation on hot reload), pollster 1, anyhow 1.

**Spec:** `docs/superpowers/specs/2026-10-21-ocean-sim-design.md`

## Verified on this machine (2026-10-21, scratch probe)

- wgpu 30.0.1 Vulkan adapter "NVIDIA RTX 2000 Ada Generation Laptop GPU" (DiscreteGpu, driver 596.71) reports `EXPERIMENTAL_RAY_QUERY`, `EXPERIMENTAL_RAY_TRACING_PIPELINES`, `TIMESTAMP_QUERY`, `TIMESTAMP_QUERY_INSIDE_PASSES`. **DX12 reports no ray query.** The Intel Arc Vulkan adapter *also* reports ray query — so "has ray query" alone does not pick the right GPU.
- egui-wgpu 0.37.0 depends on wgpu 30.0.1 and egui-winit 0.37.0 on winit 0.30.13 — no duplicate wgpu.
- RT API names in wgpu 30: `Device::create_blas(&CreateBlasDescriptor, BlasGeometrySizeDescriptors)`, `Device::create_tlas(&CreateTlasDescriptor)`, `CommandEncoder::build_acceleration_structures(blas_entries, tlas)`, `TlasInstance::new(&blas, [f32;12], custom_data, mask)`, `Tlas::as_binding()`, flags `AccelerationStructureFlags::{PREFER_FAST_BUILD, PREFER_FAST_TRACE, ALLOW_UPDATE}`, `AccelerationStructureUpdateMode::PreferUpdate`. Device needs `experimental_features: unsafe { wgpu::ExperimentalFeatures::enabled() }` and the RT limits (`max_blas_primitive_count`, `max_blas_geometry_count`, `max_tlas_instance_count`) copied from `adapter.limits()`. WGSL: `enable wgpu_ray_query;`, `var tlas: acceleration_structure`, `var rq: ray_query`, `rayQueryInitialize(&rq, tlas, RayDesc(flags, cull_mask, t_min, t_max, origin, dir))`, `rayQueryProceed(&rq)`, `rayQueryGetCommittedIntersection(&rq)`, `RAY_QUERY_INTERSECTION_TRIANGLE`.

## Global Constraints

- Must run on the NVIDIA GPU without user fiddling: explicit adapter choice **and** exported `NvOptimusEnablement = 1` / `AmdPowerXpressRequestHighPerformance = 1`. Active adapter name shown in the overlay.
- Windowed, opens at **1280×720**, renders at window resolution × render scale (default 1.0), resizable. No fullscreen.
- Performance gate: **GPU frame time p95 ≤ 12.0 ms** at 1280×720, all defaults, RT on. Vsync on by default; uncapped toggle for measurement.
- RT reflections are the **default** mode; screen-space is the comparison/fallback. If ray query is unavailable at runtime, fall back to screen-space and say so in the overlay — never crash.
- If the RT path cannot be made to work through wgpu: **stop and report to the user**; do not introduce `ash`/DXR.
- Sun-height range **−6° to 90°**. No night, moon or stars.
- Refraction is screen-space + analytic absorption/scattering. No RT refraction.
- No engine. Single exe + `shaders/` folder (embedded copies as fallback). No runtime downloads. No Python.
- Repo remote `https://github.com/cwissett-hub/ocean` (public). Nothing employer-related in the repo: no internal registry names/URLs, no work email (commits use the GitHub noreply address), no local user paths. Commit per task; push at the end of each task.
- No heavy automated GUI tests. Logic lives in pure functions tested headlessly; the window is judged by eye. GPU compute tests create a device but **never open a window**. Only the main session launches the windowed app, one instance at a time.
- Pixels on screen early: Task 1 opens a window; Task 3 shows real waves.
- Run `cargo clippy --all-targets -- -D warnings` and `cargo test` before every commit (scope `cargo test` to the module touched while iterating).

## Review Focus

1. **Wrong or missing GPU** (Intel picked, NVIDIA asleep, driver lacks ray query): pick NVIDIA Vulkan when present, otherwise run screen-space on whatever exists and print why in the overlay — test in Task 1 (`select_adapter`).
2. **Window minimised / resized to 0×0 or to odd sizes**: no surface configure with zero size, no half-res buffer of width 0 — test in Task 1 (`render_extent`).
3. **Slider extremes** (wind 25 m/s at fetch 10 km, wind 0.5, sun −6°): spectrum and buoy stay finite, no NaN reaching the GPU — tests in Task 2 (`spectrum_finite_at_extremes`) and Task 8 (`buoy_stays_finite_at_extremes`).
4. **Running for hours**: f32 phase `ω·t` loses precision; the field must be periodic in T with time passed as `t mod T` — test in Task 2 (`field_repeats_after_period`).
5. **Broken shader on hot reload**: keep the old pipeline, show the error, don't panic — test in Task 7 (`reload_rejects_invalid_wgsl`).
